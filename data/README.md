# Data directory

This directory holds the files used by CDSS Intake's local workflow and evaluation scripts. The application separates source recordings, transcripts, structured cases, answer keys, and generated reports into subdirectories.

## Contents

| Path | Purpose |
| --- | --- |
| `audio/` | Intake audio recordings. The transcription script reads supported audio files from here. |
| `transcripts/` | Transcripts saved as `.txt` files, with associated transcription metadata in `.json` files. |
| `cases/` | Structured case JSON produced from transcripts, plus model-working text files where generated. |
| `gold/` | Optional hand-written answer-key JSON files used to evaluate matching cases. |
| `reports/` | Markdown reports generated by the application. |
| `scores.csv` | Evaluation results organized by case, field, module, expected value, model value, and status. Despite the extension, this file uses `|` as its delimiter. |

Files are generally associated by their case ID (for example, `d01` or `sample-d01`). A case can be transcribed, extracted, reviewed, reported, and evaluated against a gold file with the same ID. See the [project README](../README.md) for workflow commands and the [core package README](../cdss/README.md) for storage-path details.

## Data handling and safety

- Use role-played or otherwise approved demonstration data in this repository. Do not commit real patient information, identifiable recordings, credentials, or private case files.
- Treat audio, transcripts, cases, and reports as potentially sensitive: they may contain personal or clinical details even when stored locally.
- Review data before sharing or publishing the repository, and follow your organization's privacy, consent, retention, and access-control requirements.
- CDSS Intake is a decision-support prototype, not a diagnostic or treatment system. Its sample data and evaluation results do not establish clinical suitability.
